# Disadvantages of open source software 

Free to download does not mean free to make. Someone still spends time and money building and maintaining open source software, and often those people are unpaid volunteers. Most of the disadvantages come from this. 

First is sustainability. A project may depend on one or two people. If they lose interest, burn out or change jobs, the project can be abandoned and users are left with a tool that no longer gets updates. For a researcher who needs a tool for several years, or a municipality that builds its systems on it, this is a real risk. 

Second is security. Because the code is public, anyone can inspect it, but in practice few people do. The Heartbleed bug in OpenSSL, found in 2014, showed this. A tool used all over the internet was looked after by a very small, poorly funded team, and a serious flaw went unnoticed for about two years. Open code is only safer if someone is really looking at it.

 Third is usability and support. There is often no helpdesk, only documentation and forums, which can be thin or out of date. Some tools are made by developers for developers, so a student without programming skills may struggle to install them. A municipality may need guaranteed support and training, and then has to pay for it or build it itself. 

Finally, licences come with rules. The GPL, for example, requires that changes are shared under the same terms. That can be a problem for organisations that want to keep their own additions private, so users must understand a licence before relying on a tool.
